# Ride & Collision v2 — вертикальный контакт и стены

**Статус:** approved (Дима, 2026-07-09). Реализуется.
**Контекст:** после интеграции roads-пака и суб-клеточного heightfield-грида (4378e57)
плейтест вскрыл 5 симптомов плохого контакта с рельефом. Разведка показала, что все
пять — следствия двух архитектурных решений в вертикальной модели. Этот док фиксирует
root cause и утверждённый редизайн. Игра — про езду по горкам/камням/препятствиям,
плавность контакта = core feel (см. memory `feedback_collision_contour_feel`).

## Симптомы → механизмы (разведка 2026-07-09, все file:line проверены)

| # | Симптом | Механизм |
|---|---------|----------|
| 1 | Катапульта при касании объекта сбоку (старый баг) | `groundHeight` = MAX из 5 проб (`groundProbe.ts:61`); угловая проба цепляет ВЕРХ соседнего блока → «земля» +0.5м за тик → follow-фильтр даёт impliedVy ≈ +9 м/с (`vertical.ts:138`) → на следующем тике rate-детектор отрыва (`vertical.ts:126`) выстреливает карт вверх с этой скоростью |
| 2 | Застревание намертво | `resolveTerrainSlide`: при противоположных/всех заблокированных углах нормали гасятся (`len<1e-9`, `terrainWall.ts:138`) → break без движения; выталкивания нет; байсикл каждый тик регенерит тот же heading → вечная петля |
| 3 | Приклеен на гребне (горка→спуск не даёт отрыва) | Тот же MAX по пробам: на выпуклом гребне задняя проба ещё на горке, держит max высоко → `groundRateNow` не уходит в минус → условие отрыва не срабатывает. На обрыве падают все пробы разом — поэтому трамплин→обрыв работает |
| 4 | Дрожь/чаттер на грид-тайлах | `gridSample` point-sample (12×12) = ступеньки ~10см; MAX_STEP=0.3 их пропускает; каждая ступень вниз = ложный микро-отрыв (`vy-groundRateNow≈12>4`), вверх = толчок impliedVy≈+1.85. Античаттер-тест покрывал только ±2мм |
| 5 | Клин на стыке наклонных блоков (колёса на земле) | Единственный критерий стены — `dh>0.3` на пробе (`terrainWall.ts:76`), различения склон/стена НЕТ; проба округляется в соседнюю крутую клетку → фейковая стена; клин с двух сторон → гашение нормалей → см. #2 |

Сервер карт-физику НЕ дублирует (клиент-авторитарна, `MatchRoom.ts:4`). Единственный
shared-модуль — `heightfield.ts`, его использует серверный `rocketSim.ts` — менять
семантику `sample()` синхронно с его тестами.

## Дизайн (4 правки)

### D1. Земля = поверхность ПОД картом, не max по углам
`maxGroundHeight` (центр+4 угла, MAX) заменяется на «wall-aware» выбор: пробы, чья
высота превышает высоту центральной пробы больше чем на порог ступени, — это СТЕНЫ
(ими занимается terrainWall), из ground height они исключаются. Из оставшихся — max
(колесо на бугорке всё ещё поднимает карт). Убивает катапульту (#1) и открывает
гребень для D2 (#3).

### D2. Отрыв по позиции + rate-детектор для трамплинов
К существующему rate-детектору добавляется позиционный: `groundHeight < y − snapDistance`
→ airborne (баллистика). Пока grounded — y следует за землёй exp-фильтром как раньше.
**Дефолт настройки — «как в оригинале»: на скорости с холмиков подлетать** (решение
Димы 2026-07-09), без фанатизма. `snapDistance` и порог rate-детектора — крутилки
тюнера; ими калибруется охотность отрыва.

### D3. Билинейный gridSample + различение склон/стена по градиенту
Point-sample в `gridSample()` (осознанное, но ошибочное решение T1) заменяется
билинейной интерполяцией: ступени 10см размазываются в честный ездабельный склон,
стена 1.1м даже после интерполяции остаётся стеной по градиенту. В `cornerBlocked`
критерий «ступень > MAX_STEP» дополняется градиентным: стена = крутизна выше порога
на КОРОТКОЙ дистанции (две пробы вдоль движения), а не разница высот на полкорпуса.
Чинит #4 и #5. Синхронно: серверный rocketSim использует `sample()` — прогнать его тесты.

### D4. Слайд без деадлока
Ветка «нормали погасились/всё заблокировано» в `resolveTerrainSlide` получает
выталкивание из проникновения (по образцу MTV в `staticSlide.ts`) вместо полной
заморозки. Инвариант: карт НИКОГДА не может застрять так, чтобы ни одно направление
(включая назад) не работало.

## Параметры (тюнер)

Все новые пороги — `@export`-стиль параметры в `physics/types.ts` рядом с
существующими vertical-параметрами (gravity, followRate, airborneDropThreshold),
с описаниями по правилам `.claude/rules/param-tuner-descriptions.md`:
- `groundSnapDistance` — насколько земля должна уйти вниз, чтобы карт оторвался.
  Меньше = взлетает на каждом бугорке, больше = липнет к спускам.
- порог исключения проб из ground height (D1) — по умолчанию = MAX_STEP.
- порог градиента склон/стена (D3).

## Регрессия

1. Юнит-тесты на каждый механизм: катапульта у бока блока (проба на верхушке соседа
   НЕ даёт vy-импульс), гребень → отрыв на скорости, грид-лесенка → ноль ложных
   отрывов, стык склонов → ноль блокировок, деадлок-сценарий → выталкивание.
2. Существующие vertical/terrainWall тесты обновляются ОСОЗНАННО (трамплин-контракт
   сохранить: crawl не взлетает, cruise взлетает).
3. E2E: скриптовые заезды `__runScript` по диагностической карте (гребень, лесенка,
   бок блока, стык склонов) с ассертами по `__trace`: max |vy| на ровных участках,
   ноль нулевых перемещений при ненулевом throttle, отрыв на гребне при cruise.

## Вне скоупа этого захода
- Мосты / мульти-слойный heightfield (следующая задача, данные в bake уже есть).
- Подвеска как визуальный эффект (наклон корпуса на ступеньках) — polish later.
- Скорость падения («слишком быстро падает» по ощущению Димы) — отдельная калибровка
  gravity в тюнере после v2, не архитектура.
